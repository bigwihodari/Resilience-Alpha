🚀 Guide de lancement

Resilience-Alpha — montage 5 PC. Suivez votre rôle, pas à pas.

① Sur chaque PC Docker, Git, le projet ② Le réseau point d'accès, IP, pare-feu ③ Host principal cockpit + banque + haute-dispo ④ Host backup secours (bascule auto) ⑤ Clients app de paiement ⑥ Attaquant 7 vecteurs, multi-attaque ⑦ Ordre & dépannage ⑧ Mode jeu idle éco vs cyber

1Sur CHAQUE PC (une fois)

1
Docker Desktop installé ET démarré (icône 🐳 → « Engine running »).
2
Git installé.
3
Récupérer le projet (avec internet, WiFi de l'école) : 
git clone https://github.com/bigwihodari/Resilience-Alpha.git
cd Resilience-Alpha

2Le réseau du groupe (point d'accès)

Point d'accès spécial, ou WiFi de l'école ?

➡️ On utilise le point d'accès mobile de Windows du PC principal, pas le WiFi de l'école (qui isole les PC entre eux → la démo ne marcherait pas). Le sujet l'impose.

A. Ouvrir le point d'accès (sur le PC PRINCIPAL)

1
Paramètres → Réseau et Internet → Point d'accès sans fil mobile → Activer.
2
Modifier : nom du réseau (SSID) = RESILIENCE-G<n> (votre n° de groupe) + un mot de passe.
3
Partager depuis « Wi-Fi » : le principal peut rester sur le WiFi école (il partage sa connexion).
Raccourci : Win + A → Point d'accès sans fil mobile.

B. Connecter les 4 autres PC

Backup, Client-A, Client-B, Attaquant : se connecter au Wi-Fi RESILIENCE-G<n>.

C. Trouver les adresses IP (sur chaque PC)

ipconfig | findstr IPv4
  • Le PC principal (qui héberge le point d'accès) = 192.168.137.1.
  • Les autres = 192.168.137.x — notez l'IP du backup (ex. 192.168.137.2).

D. Pare-feu (si un PC n'atteint pas le serveur)

Sur le principal et le backup, en PowerShell administrateur :

netsh advfirewall firewall add rule name="Resilience-Alpha" dir=in action=allow protocol=TCP localport=8000,8001,8080,3000,9090

Et passez le réseau RESILIENCE-G<n> en profil Privé.

3🖥️ HOST-PRINCIPAL (serveur principal)

Serveur principal + cockpit · IP 192.168.137.1
1
Fichier .env (racine) — mettez l'IP réelle du backup : 
ROLE=primary
JWT_SECRET=choisir-un-secret-commun
REPL_TOKEN=choisir-un-token-commun
# Haute dispo : vers le PC de secours (pour le visuel + la bascule du cockpit)
PEER_API_URL=http://192.168.137.2:8000
HOST_BACKUP=192.168.137.2
HOST_BACKUP_API_PORT=8000
HOST_BACKUP_AUTH_PORT=8001
JWT_SECRET et REPL_TOKEN : identiques sur le backup. Sans backup, laissez PEER_API_URL vide et HOST_BACKUP=api (valeurs par défaut).
2
Lancer : .\start.ps1 (ou ./start.sh)
3
Vérifier : http://localhost:8080 → cockpit (connexion alice / password123).
4
Trois espaces dans l'app host :
  • Cockpit — KPI live (débits, latences, erreurs, CPU/mémoire), détection IA, remédiation, sécurité.
  • Haute-Dispo — visuel live PRINCIPAL ⇄ SECOURS : qui sert le trafic, décision de l'IA, journal des bascules.
  • Banque — connexion banquier / password123 : gérer tous les comptes (créditer / débiter), historique, en temps réel.

Mettre à jour : .\update.ps1 · Redémarrer (après modif du .env) : .\restart.ps1 · Arrêter tout : .\stop.ps1

4🖥️ HOST-BACKUP (serveur de secours)

Réplique le principal, prend le relais s'il tombe
1
Fichier .env (racine) — mêmes secrets que le principal : 
ROLE=backup
PEER_API_URL=http://192.168.137.1:8000
JWT_SECRET=le-meme-que-le-principal
REPL_TOKEN=le-meme-que-le-principal
2
Lancer : .\start.ps1 (il affiche « rôle : backup »).
✅ Bascule & retour automatiques : si le principal tombe, le secours est promu tout seul (au bout de ~6 s) et sert le trafic. Quand le principal revient, le secours lui réplique son état (aucune transaction perdue) puis lui rend la main. Tout est visible en direct sur la page Haute-Dispo du cockpit.

6⚔️ ATTAQUANT (console d'attaque)

Attaque le serveur principal — labo uniquement
1
cd attacker
2
Fichier attacker/.env : 
TARGET_URL=http://192.168.137.1:8080
TARGET_HOST=192.168.137.1
3
Lancer : .\start.ps1 → http://localhost:8090
4
7 vecteurs d'attaque disponibles, cochables un par un ou plusieurs à la fois : saturation (DoS), injection SQL, flood API, XSS, bourrage d'identifiants, flood 404, slowloris.
5
Régler l'intensité / la durée, puis « Lancer la sélection » — ou « TOUT LANCER » (les 7 d'un coup) pour saturer et faire tomber le principal : on voit alors le secours prendre le relais sur la page Haute-Dispo du cockpit.
6
🎯 Zone « Reconnaissance / Opération » (le jeu), sous le panneau d'attaque :
  1. SONDER la cible (discret) → fuite progressive (comptes, soldes approximatifs, livret) et astuces débloquées.
  2. Les astuces arrivent de deux façons : au minuteur (« prochaine astuce dans mm:ss ») et à chaque succès (fuite ou butin).
  3. Après assez d'infos : TENTER UN RETRAIT (vol plafonné) sur le compte courant ou le livret → butin cumulé affiché.
  4. Dose ! Trop de retraits (butin trop gros) ou une attaque trop forte → l'IA te repère : COOLDOWN (attaques refusées), bascule secours et butin annulé (restauré sur la cible). Reste discret pour gagner.
📖 Explication détaillée du mode jeu (pour non-dev) : GUIDE-ATTAQUANT.html (à la racine du projet) — aussi accessible depuis la console via le lien « comment ça marche ? ».

7Ordre d'allumage & dépannage

Le jour J, dans l'ordre :
1
Principal : ouvrir le point d'accès + start.ps1 (vérifier le cockpit).
2
Backup : se connecter au PA + start.ps1.
3
Clients A/B : se connecter + client/.env + start.ps1.
4
Attaquant : se connecter + attacker/.env + start.ps1.
5
Scénario de démo conseillé :
  1. Les clients A/B se paient ; le banquier (page Banque) crédite/débite des comptes → tout bouge en direct partout (WebSocket).
  2. L'attaquant lance plusieurs vecteurs / « TOUT LANCER » sur le principal ; le cockpit montre la détection IA puis la remédiation (bouclier, canari).
  3. Le principal sature et tombe → page Haute-Dispo : le SECOURS est promu et sert le trafic ; les clients continuent à payer (bascule nginx, aucune transaction perdue).
  4. On stoppe l'attaque : le principal se répare → retour automatique au principal (réconciliation) ; le solde est intact.
  5. Variante « jeu de hacker » (zone Reconnaissance/Opération de la console) : l'attaquant sonde en douce, débloque des astuces, réussit un petit vol discret (butin conservé) ; puis il force (gros butin ou flood) → l'IA bloque (cooldown affiché), bascule sur le secours et neutralise le butin → l'argent volé ne « gagne » pas. Cooldown écoulé → retour normal.

8🎮 Mode jeu (idle « éco vs cyber »)

Par-dessus la démo de paiement, l'app est un jeu idle multijoueur : premier à 1 000 000 € gagne (joueur OU attaquant). Rien à installer de plus — mêmes serveurs.

🎮 Joueur (app client, :8095)

  • Fortune & course au million : barre de progression + classement live.
  • Livrets & Shop : plusieurs livrets qui produisent des intérêts (idle), boutique à coûts exponentiels (nouveaux livrets, multiplicateur, coffre-fort).
  • Marché : boîte mail, enchères (le plus offrant gagne la valeur de l'objet), quiz du banquier.
  • Chat (global + salons privés) et mini-jeu Dino (ramasse des pièces, bonus x5/x10/x100 → argent).

🏦 Banquier (host, onglet Jeu — banquier / password123)

Lance des enchères et des quiz, et vend de l'info aux attaquants (insider). Règle aussi le taux du livret (onglet Banque).

⚔️ Attaquant (console :8090)

  • Reconnaissance → vol plafonné sur les clients, la banque (gros risque) ou d'autres attaquants (PvP).
  • Shop furtivité (payé au butin), achat d'info au banquier, campagnes de phishing (fausses enchères).
  • Jauge de suspicion : plus tu attaques fort, plus l'IA risque de te bloquer (cooldown) — joue discret.
🛡️ Côté défense : le Cockpit montre la détection IA, la suspicion par IP, la remédiation et la bascule sur le secours si le principal est compromis (le butin volé est neutralisé si l'IA bascule à temps).
